# Committee and Group Email Guide

This page explains what a committee/group email address is and how to use it.

If you are a participant using a personal email (Gmail, Yahoo, etc.), this page is for you.

## Short Answer

Send committee-wide messages from your own email account to the committee/group mailing-list address.

When you email that address, your message goes to all current participants.

## Why This Is Useful

- You send one email to everyone without typing each person's address.
- Group correspondence is archived separately for record-keeping.
- New participants receive future group messages; ask the chair for earlier correspondence they need. Joining does not deliver the past email archive to a personal inbox.

## What This Address Is For

- Send updates to the whole committee/group
- Ask the whole group a question
- Share meeting notes or next steps with everyone
- Keep group communication in one place

## What This Address Is Not For

- Private one-to-one conversations
- Sensitive information that should only go to staff or leadership
- File attachments that belong in SharePoint long term

For long-term files, upload to the committee SharePoint Documents library first. Email the committee site address from [Quick Links](/link/3), folder and file name. Follow the [SharePoint screenshot guide](/link/7); do not use Share or Copy link for the external-member handoff.

## Which Email Address Should I Use To Send?

Use your own email account: your personal email or your requested SHHA mailbox, whichever the office added to the group.

You do **not** log in directly to the group address as a mailbox.

The group address is a distribution address, not a personal account.

## Quick Decision Flow

1. Need everyone in the committee/group to see this? Use the committee/group mailing-list address.
2. Need only one person to see this? Email that person directly.
3. Sharing a document people will keep working on? Put it in the committee SharePoint Documents library and email the committee site address, folder and file name to the committee/group address.

## FAQ

### "Should we use this as the preferred email address for the committee/group?"

**Yes.** Use it for group-wide communication.

### "Can we send mail from this address?"

**No.** Participants should send from their own email account to the group address.

### "Do I need to use Teams because Microsoft mentioned Teams in invitation emails?"

**No.** External volunteers should use email and SharePoint links.

If Microsoft emails mention Teams, that is default wording and can be ignored for this workflow.

# SharePoint Folder Organization

This page explains where committee materials belong, how committee members work with SharePoint files, and how internal office users keep group-owned document libraries convenient without sending external members into OneDrive.

## Short Version

Every committee has two official places for committee-related materials:

- An **Office folder** for staff-facing committee work.
- A **SharePoint folder/site** for committee, volunteer, Board, and shared working materials.

Those folders provide a consistent structure so staff, volunteers, committee members, and Board members know where to find information. To make that system work, committee-related materials need to stay in those locations.

If there are office-only working documents, separate issues, drafts that do not belong in the committee record, or staff-only administration files, those should have their own workspace outside the committee folders.

## Sharing A File With The Board Or A Committee

**Do not use Share or Copy link as the file handoff for external Board or committee members.** Use the committee site address, folder and file name; see the [screenshot guide](/link/7). Instead, move the file into the SharePoint folder that belongs to that group. Access comes from membership in the group's SharePoint/Microsoft 365 group.

This matters because many Board and committee members use personal email addresses, such as Gmail. Access depends on approved site and document permissions, not an email suffix. Copying a link points to a file; it does not by itself give its recipient permission. External members should access group files through the appropriate SharePoint site.

### File-Sharing Decision Flow

### The Reliable Board Workflow

1. Find the file in OneDrive or the Office folder.
2. Move it into **Board - SharePoint**.
3. Tell Board members to open the [Board SharePoint page](https://shha.sharepoint.com/sites/BOARD) and locate the file.
4. If helpful, email the Board the folder name and file name. Do not use **Share** to create separate individual permissions.

**Remember:** **Board - Office** is for office staff work. **Board - SharePoint** forms the Board SharePoint document library and is the correct place for files Board members need to access.

The advantage of this slightly peculiar Microsoft arrangement is a clear separation between files intended for a specific group and files intended for general internal office use. The disadvantage is that Microsoft has once again made a folder name carry the emotional weight of a small policy manual.

## Why This Matters

The goal is boring in the best possible way: people should know where things are.

When committee files live in predictable places:

- Staff can find the current working file without asking three people.
- Volunteers and committee members can use the same SharePoint links over time.
- Board members can review materials without hunting through personal folders.
- Role transitions are less painful because files are not trapped in one person's OneDrive.
- The committee record stays coherent.

## What Belongs In Committee Folders

Use the committee Office folder or SharePoint folder for:

- Meeting materials
- Minutes and agendas
- Committee reports
- Working drafts that the committee needs
- Reference documents
- Photos or supporting materials for committee work
- Files that future committee members should be able to find

Do not keep committee materials only in a personal OneDrive folder, email attachment, desktop folder, or private side folder.

## What Should Live Somewhere Else

Use a separate workspace outside the committee folders for:

- Office-only working notes
- Staff-only administration files
- Personnel or confidential documents
- One-off issues that are not part of the committee record
- Drafts that are not ready to share with the committee
- Separate projects that should not clutter the committee folder

If in doubt, ask: “Will a future committee chair, staff member, or Board member reasonably expect to find this in the committee record?” If yes, use the committee folder. If no, use a separate workspace.

## Documents Shared With Board

To help preserve institutional knowledge and make important committee information easier to find, each committee SharePoint site now contains a folder called **Documents Shared with Board**.

These folders are linked from the [Board SharePoint site](https://shha.sharepoint.com/sites/BOARD), so Board members can access committee reference materials from a single location.

This area is for documents that should be available to Board members but are not necessarily appropriate for public distribution. Useful examples include:

- Legal analyses
- Committee procedures
- Information related to ongoing disputes or projects
- Committee charters
- Resident welcome materials
- Other enduring reference documents

At launch, these folders may be empty. Committee chairs should add useful files as they identify them. Office staff can also assist.

In general, use this space for enduring documents that Board members may need to reference months or years later. The goal is to keep important information from being buried in monthly meeting folders or old email threads.

Committee members have full read/write access to their respective committee SharePoint sites and can add documents as needed.

For the full list of direct links to committee SharePoint sites and document libraries, visit the [Quick Links &amp; Directory](https://wiki.sandiahomeowners.org/books/shha-it-help-guide/page/quick-links-directory) page and scroll to **SharePoint Sites (Committee Document Libraries)**.

If you encounter issues or have suggestions for improvement, contact Anna or Heidi.

## How Committee Members Add Or Remove Files

Committee members can create, upload, edit, move, and delete files within their committee's SharePoint document library. That includes members using SHHA Microsoft accounts and approved external accounts, as long as they are members of the committee's SharePoint/Microsoft 365 group.

To add a file:

1. Open the committee SharePoint site.
2. Open the **Documents** library.
3. Open the correct folder.
4. Use **Upload** for an existing file, or **New** to create a new Word, Excel, PowerPoint, folder, or other supported file.
5. Confirm the file appears in the committee folder, not in a personal OneDrive folder.

To edit, move, rename, or delete a file:

1. Open the file or select it in the **Documents** library.
2. Use the toolbar or right-click menu for actions such as **Rename**, **Move to**, **Copy to**, or **Delete**.
3. For shared committee materials, prefer **Move to** over downloading and re-uploading. That keeps version history and links more intact.

**Small caution:** because committee members have write access, deleting or moving files affects everyone. If a folder looks old but might be part of the committee record, ask before tidying it into oblivion. SharePoint has a recycle bin, but “let's not test the recycle bin today” is usually the happier workflow.

## Office Staff: Adding A SharePoint Folder To OneDrive

**This shortcut is for internal SHHA users only.**

1. Open the committee SharePoint site.
2. Open the **Documents** library.
3. Select **Add shortcut to OneDrive** or **Add shortcut to My files**.
4. Confirm the library appears under **My files** in that user's OneDrive.

The shortcut points to the original group-owned SharePoint library. It does not create a copy. Each internal user must add the shortcut while signed in to their own account.

**External committee members should not use OneDrive for committee documents.** Members using Gmail, Yahoo, iCloud, or another personal email address must bookmark the committee SharePoint site and work in the Documents library through their browser.

## Committee SharePoint Permissions

Each committee SharePoint site is connected to its SharePoint/Microsoft 365 group. Membership in that group controls access to the committee document library.

- **Committee members:** Contribute access to Documents. They can create, upload, edit, move, and delete documents.
- **Office staff:** Owner / Full Control access. They manage membership, permissions, navigation, and the SharePoint home page.

Committee chairs do not need site-owner access or an `@sandiahomeowners.org` account to work with documents. Keeping page administration with office staff avoids handing a volunteer an accidental cockpit full of Microsoft switches.

Changes to Microsoft 365 group membership automatically update access to the committee's SharePoint documents.

## Group-Owned SharePoint Libraries

Committee SharePoint Documents libraries are owned by the committee's Microsoft 365 group. They are not folders in Anna's personal OneDrive and should not be shared person-by-person.

Office staff create or administer the group-connected site and manage membership. Committee members receive document access through group membership. Internal office users may add the Documents library as a OneDrive shortcut; external members use the SharePoint site directly.

## Important OneDrive Notes For Office Staff

- OneDrive shortcuts are only for internal office users with SHHA Microsoft accounts.
- Each internal user adds the shortcut while signed in to their own account.
- Do not download and re-upload the library or create a separate copy.
- Do not rename or move the top-level shortcut casually.
- External committee members use SharePoint only and should never be given OneDrive instructions.

## Office Folder Versus SharePoint Folder

Use the **Office folder** for staff-centered committee support work that needs to stay coordinated among office/admin users.

Use the **SharePoint folder/site** for committee-facing materials and documents that volunteers, committee members, Board members, or future role holders need to access.

Both matter. The main rule is not “everything goes everywhere.” The rule is “committee-related materials belong in the official committee structure, and unrelated/private work belongs somewhere else.”

# SHHA Reminders

**Who this is for:** staff and volunteers with approved Reminders access. Start by checking the event in its calendar, then open [SHHA Toolbox](https://toolbox.sandiahomeowners.org/.auth/login/aad?post_login_redirect_uri=%2Ftools) and choose Reminders.

Sign in with your approved SHHA Microsoft account or invited personal-email identity. An SHHA email suffix is not required. Tool access is separate from sign-in; contact IT Help if the card is Restricted.

## Check the event in the right calendar

1. **Board meetings:** the Office organizer creates or edits the Teams/Outlook meeting and invites `admin@sandiahomeowners.org`, including updates and cancellations. That address receives invitations; staff do not maintain duplicate meeting dates there.
2. **GRIT deadlines:** staff maintain the selected deadline in SHHA’s public Google calendar and mark it Free so it does not reserve the room. The submission guide maintains the publication deadline policy.
3. Refresh the calendars in Reminders when needed. The tool imports dates; calendar invitation text does not create or authorize a reminder.

## Create and activate a reminder

1. Open **Upcoming emails**. List and Mini calendar show email send dates in Mountain time, not just meeting dates. Select an email to inspect its message, recipients, From/reply address and event.
2. Choose **New reminder → Choose event**. Select the exact Board meeting, GRIT deadline or other imported event.
3. Select **This occurrence only** or **Every future occurrence**. Set up a recurring series once.
4. Write the emails and check exact recipients, From/reply address and timing. All-day deadlines need a send time. Check the actual dates across daylight-saving changes.
5. Select **Save draft &amp; review**. Read the rendered messages and next actual send dates. A saved draft does not send.
6. When the preview is correct, select **Activate reminder**. This authorizes future scheduled sends. Saving later changes returns the setup to draft; review and activate it again.
7. Use **Manage reminders** to find drafts, active or paused setups and completed one-time reminders. Use **Delivery history** to review earlier attempts.

Saved messages and recipient groups are shortcuts copied into a setup. Editing the library later does not silently update existing setups. Review the actual setup before activating it.

## If something is wrong

Canceled occurrences do not send. A successful send is not repeated just because the event or wording changes. New approvals cover future sends, not missed historical dates.

# Committee SharePoint Guide

**Audience:** SHHA committee and task-force members. Office staff handle site setup, membership, permissions, and changes to the SharePoint home page.

**Start here:** open your committee site from [Quick Links &amp; Directory](/link/3). A document library is the shared file cabinet called **Documents**. If you have not accepted your Microsoft invitation, first follow [the invitation and sign-in guide](/books/shha-it-help-guide/page/volunteer-without-shha-email).

## Send people to the site, folder and file

**Do not use Share or Copy link to hand files to external committee or Board members.** Put the file in the correct group-owned SharePoint Documents library. In your email, give the committee site address from [Quick Links &amp; Directory](/link/3), then the folder and file name. Members open that site and find the document there.

A file-sharing link is not the SHHA handoff method for external members: it can lead to a permission prompt even when the sender can open the file. Approved group membership supplies access; copying a link does not grant it. This is SHHA's supported workflow, not a rule that all personal-email accounts are technically unable to open Microsoft links.

## Email And Documents Are Two Different Tools

## External Members: Use SharePoint, Not OneDrive

If you use Gmail, Yahoo, iCloud, or another personal email address, access committee documents only through the committee SharePoint site in your browser.

- Bookmark the committee SharePoint site.
- Sign in with the same personal email address that received the SHHA Microsoft invitation.
- Do not try to add the committee folder to OneDrive.
- Do not move committee files into a personal OneDrive.

This is the standard SHHA workflow for external committee members. It keeps everyone working from the same group-owned document library.

## What Committee Members Can Do

Committee members have read/write access to the **Documents** library. You may:

- Open and download documents
- Create folders
- Upload files
- Create Word, Excel, or PowerPoint files
- Edit and rename files
- Move files within the Documents library
- Delete files that should no longer be kept

Deleting or moving a file affects everyone, so ask before reorganizing material that may be part of the committee record.

## How To Edit, Move, Or Delete A File

1. Select the file using the circle beside its name, or right-click it.
2. Choose **Open**, **Rename**, **Move to**, or **Delete**.
3. Use **Move to** when reorganizing files. Do not download and re-upload a file just to move it.

## Documents Shared With Board

Use **Documents Shared with Board** for enduring reference material Board members may need later, such as procedures, legal analyses, project background, charters, or other non-public reference documents.

If future Board members may need it, do not let it disappear into an old email thread.

## How To Share A File With The Committee

Put the file in the committee SharePoint Documents library, then email the committee mailing list with the committee site address, folder location and file name. For example: “Open the Board site from Quick Links, then Documents → Minutes → Draft meeting notes.docx.” The folder and filename in this example are illustrative.

Do not use the Share button to grant the committee access. Group membership already provides document access, including for approved members using personal email addresses.

## Why The President Has Two Email Addresses

Short version: `robin.otten@sandiahomeowners.org` is Robin's personal SHHA account. `president@sandiahomeowners.org` is the President mailbox. One belongs to the person; one belongs to the office.

<table id="bkmrk-addresswhat-it-isuse"> <thead> <tr><th>Address</th><th>What it is</th><th>Use it for</th></tr> </thead> <tbody> <tr> <td>`robin.otten@sandiahomeowners.org`</td> <td>Robin's own SHHA sign-in and personal work account</td> <td>Signing in to Microsoft, opening Outlook/SharePoint, and messages meant specifically for Robin as a person</td> </tr> <tr> <td>`president@sandiahomeowners.org`</td> <td>The shared President inbox</td> <td>Official President business that future Presidents may need to see later</td> </tr> </tbody></table>

Yes, two inboxes is annoying. Think of it as a key and a filing cabinet: Robin's account is the key that lets her into Microsoft; the President inbox is the filing cabinet that stays with the office when the next President takes over.

This is why SHHA keeps both addresses:

- **Continuity:** President email history stays with the President role.
- **Less confusion later:** The public address does not change every time the role changes.
- **Record keeping:** Important President conversations are not stranded in one person's personal mailbox.
- **Cleaner handoff:** IT can give the next President access to the same role inbox.

**Simple rule:** if it is official President business, use `president@sandiahomeowners.org`. If it is about Robin personally, use `robin.otten@sandiahomeowners.org`. If you are not sure, the President inbox is usually the safer mailbox for SHHA business.

<a id="bkmrk--1"></a>## I was invited but cannot access files. What is usually wrong?

The most common cause is that the original Microsoft invitation email was never accepted. Until you accept that invitation, Microsoft does not recognize you as an authorized guest, so SharePoint links and group emails will not work.

### How to fix it — step by step

1. **Search your email** (Gmail, Yahoo Mail, iCloud Mail, etc.) for a message from **"Microsoft Invitations"** with a subject like *"You've been invited to access applications within the Sandia Homeowners organization."* Check your **Spam / Junk** folder — these invitations often land there.

3. **Sign in with your personal email address** — the same one the invitation was sent to. If you already have a Microsoft account linked to that email, use its password. If not, Microsoft will walk you through creating one (free) or send a one-time passcode.
4. **Review and accept the permissions prompt.** Microsoft will ask you to agree that SHHA can see basic profile information (name and email). Click **Accept**.
5. **Try opening your SharePoint link again.** It should now work.
 
If you cannot find the invitation email or the link has expired, contact **ITHelp@sandiahomeowners.org** and they can resend it.

<a id="bkmrk--32"></a>## How does the email transition work when someone enters or leaves a role? Who handles it?

There is **no automatic overlap**. If you want your successor to start seeing emails before your access is removed, ask office staff to add them early. A brief overlap is good practice.

# GRIT Contributor Guide

*Send this page to neighbors, committee chairs, Board members, and volunteers who want to contribute to the GRIT.*

**Note:** This is practical writing and photo guidance, not the official publication policy. Read the [GRIT content rules and submission guide](/books/shha-it-help-guide/page/grit-content-rules-and-submission-guide) for the approved section rules and submission process. Approvals and final editorial decisions remain with the Communications &amp; Publications Committee and the current GRIT editor.

## Welcome

The GRIT is the community newsletter of Sandia Heights. It is not a newspaper, a social media feed, or an HOA enforcement bulletin.

It is a place for neighbors to share information, ideas, stories, photographs, events, accomplishments, local history, and community knowledge.

The best articles help residents feel more connected to the place they live and the people who live here.

## Quick Submission Tips

- Write for a neighbor holding the printed GRIT in their hands.
- Make the local connection obvious: why does this matter in Sandia Heights?
- Send original image files separately instead of embedding them in a Word document.
- Include captions and names for people in photos when possible.
- Use a clear title and include dates, locations, and contact information when relevant.
- Expect light editing for clarity, length, style, and available space.

## Know Your Audience

The GRIT is primarily a print publication. Approximately 1,800 printed copies are distributed each month.

A digital version is also emailed and posted online, but only a few hundred readers typically access the issue electronically.

**Write for someone holding a printed copy in their hands.** If a link or QR code is useful, include it, but do not make the article depend on readers clicking around online.

## What Makes Good GRIT Content?

Ask yourself: **Why should a Sandia Heights resident care?**

Good topics often include:

- Local wildlife
- Gardening in Sandia Heights
- Hiking and trails
- Neighborhood history
- Volunteer efforts
- Community events
- Local organizations
- Wildfire preparedness
- Astronomy and dark skies
- Interesting neighbors
- Practical homeowner knowledge
- Kids' activities
- Seasonal topics

The strongest articles are relevant to both place, meaning Sandia Heights, and time, meaning what is happening now.

## Avoid HOA Nag-Grams

Readers generally do not enjoy being scolded. Instead of "Residents should stop doing X," try "Here is why X matters."

Teach. Explain. Entertain. Tell stories. Share useful information.

A reader who learns something interesting is more likely to change behavior than a reader who feels criticized.

## Bring Your Personality

The GRIT does not need to sound like a government report. Humor, storytelling, local anecdotes, and personal experiences are welcome.

Articles can be informative while still being warm, neighborly, and enjoyable to read.

## Photographs Matter

The printed GRIT is black and white. An image that looks beautiful in color may become muddy and difficult to understand when printed.

### Good Photos

Useful photos usually have:

- Strong contrast
- A clear subject
- Simple composition
- A large foreground object
- Distinct separation between subject and background

### Photos That Are Hard To Print

Photos often print poorly when they have:

- Distant subjects
- Heavy shadows
- Low contrast
- Busy backgrounds
- Lots of similar colors that become the same shade of gray

## Image Guidelines

Whenever possible:

- Submit original image files.
- Do not embed images inside Word documents.
- Provide captions.
- Identify people in photographs.
- Submit multiple image options.

The editor may crop, resize, or adjust images for publication.

## Length

Shorter is usually better.

- **Announcement:** 50-150 words
- **Short article:** 200-500 words
- **Feature article:** 500-1,000 words

If an article is longer, the editor may shorten it for space.

## Final Thought

The best GRIT articles answer one question: **What would make a neighbor stop flipping pages and read this?**

If the article is local, timely, useful, interesting, or amusing, you are probably on the right track.

# GRIT Internal Production Reference

Internal reference for the Communications &amp; Publications Committee, GRIT editor, layout volunteers, and office staff. This page tracks the working rhythm and handoffs behind each issue.

This page covers the production schedule, responsibilities, and approval sequence.

## Purpose

The Communications &amp; Publications Committee produces the GRIT, the monthly community newsletter of the Sandia Heights Homeowners Association.

This page is an internal operating reference. It is not the public contributor guide and it is not a replacement for official publication policy.

## Audience And Format

- **Primary medium:** printed newsletter, approximately 1,800 copies distributed monthly.
- **Secondary medium:** digital PDF distributed by email and posted online.
- **Digital reach:** email distribution reaches approximately 3,000 subscribers, with typical open/click rates of 200-300 readers per issue.

Because most readers receive the printed edition, publication schedules and content selection should prioritize the print audience.

## Monthly Schedule

### Before the submission deadline: Content collection

Committee chairs, Board members, residents, and staff submit articles, announcements, photographs, classifieds, and other content.

Submissions should be entered through [sandiaheightsgrit.app](https://sandiaheightsgrit.app).

### 1st of the preceding month: Submission deadline

Submit content by the **1st of the month preceding publication**. For example, submissions for the December issue are due November 1. Late submissions may be held for a future issue.

### 20th-25th: Editorial Review

The Editor:

- Reviews submissions
- Performs copy editing
- Requests revisions if needed
- Selects photographs and artwork
- Determines article placement
- Resolves layout constraints

The Editor may shorten or edit submissions for clarity, space, style, and consistency.

### 25th-29th: Layout And Proofing

The Editor and layout volunteers:

- Assemble the issue in Adobe InDesign
- Verify links, captions, dates, and contact information
- Prepare advertisements and classifieds
- Generate proof PDFs

Committee members review the PDF draft and provide comments. In the current Google Drive monthly issue folder under **shhagrit@gmail.com**, create a **Draft review** folder, put the draft PDF there, then right-click the folder and choose **Share → General access → Anyone with the link → Commenter**. Send reviewers the folder link with a comment deadline.

After the comment period, the editor sends required changes to the layout assistant through Upwork. The layout assistant reads the layout package from Google Drive and uploads the revised layout and PDF back there. Check that the edits have been implemented. The layout assistant creates a **new final PDF with the edits incorporated**; retain the original draft PDF and its comments as a separate file. Follow the [draft review and final-PDF sharing steps](https://wiki.sandiahomeowners.org/books/shha-it-help-guide/page/grit-monthly-editor-procedure#bkmrk-8.-review-the-pdf-an).

### Final Board / Secretary Review And Printer Access

After comments and edits are complete, place the **new final PDF** in a separate **Final** folder in the monthly Google Drive issue folder, outside the draft-review folder. Share the **PDF itself** as **Anyone with the link → Viewer**. Send the new PDF's view-only link to the **Board for an early preview**, the **printer**, the **Secretary**, and **the Office**, identifying the current issue/version.

This gives the printer direct access to the final PDF in Google Drive and avoids passing large PDF files around as email attachments. It also lets the printer prepare the proof in parallel while content review is finishing.

The Google Drive link should be treated as the authoritative file for the issue. Avoid sending large PDF attachments unless there is a specific reason.

### Proof Approval

The Office reviews and approves the printer proof after the Secretary has approved the issue content.

Normal path:

1. Editor sends the view-only final-PDF link to the Board for an early preview, the printer, the Secretary, and the Office.
2. Printer uses the Google Drive PDF to prepare the proof in parallel.
3. Secretary approves the content.
4. The Office reviews the printer proof.
5. The Office approves the proof if it matches the approved content.

If the Secretary requests changes, which should be infrequent:

1. The Office does not approve the proof.
2. The editor makes the requested content change.
3. A new revised final PDF is uploaded to Google Drive and its current view-only link is sent to the Board, printer, Secretary, and the Office.
4. The printer prepares a revised proof.
5. The Office reviews and approves only after the corrected content is approved.

### Printer Handoff

The printer should have access to the final Google Drive PDF link as early as practical once the issue goes to Board / Secretary review.

Office staff and the editor should confirm:

- The printer can access the Google Drive file.
- The printer knows which PDF is the final/current version.
- The proof is based on the Secretary-approved content.
- The expected print completion and delivery timing are clear.

### Distribution

Office staff:

- Coordinate printed newsletter distribution.
- Send email distribution.
- Post the digital version online.

### Long-term source archive

After approval, the editor obtains the complete editable source package from the layout assistant and preserves it in the Office's **OneDrive monthly issue folder**. Sign in with **griteditor@sandiahomeowners.org**, the same account used to collect the ads. Keep the InDesign source and linked assets, final edited text, approved PDF, and approved printer proof together for long-term archiving. See the [full archive checklist](https://wiki.sandiahomeowners.org/books/shha-it-help-guide/page/grit-monthly-editor-procedure#bkmrk-archive-full-package).

## Working Roles

- **Communications &amp; Publications Committee:** owns the GRIT as a committee function and supports editorial direction.
- **Editor:** reviews submissions, edits copy, selects content, resolves fit/placement, sends the final issue for review, and gives the printer direct Google Drive access.
- **Secretary:** approves the content before the proof is approved.
- **Printer:** uses the Google Drive PDF to prepare the proof in parallel with final content review.
- **Office:** reviews and approves the printer proof after Secretary approval, coordinates print/distribution handoff, and holds approval if content changes are requested.
- **Layout volunteers:** assemble the issue in InDesign and prepare proof PDFs as needed.

## Internal Checkpoints

- Are events still timely by the time the printed GRIT reaches residents?
- Are dates, locations, names, contact details, and URLs checked?
- Are photos likely to work in black-and-white print?
- Are ads and classifieds in the correct issue folder?
- Is the final Google Drive PDF link clearly identified as the authoritative version?
- Has the printer been copied or otherwise given direct access to the Google Drive PDF?
- Has the Secretary approved the content?
- Is the Office approving the proof only after content approval?
- If changes are requested, has proof approval been held until the revised content is ready?

## Goal

The purpose of the schedule is to ensure that:

- Events are announced before they occur.
- Information remains timely and useful.
- Print readers receive current content.
- Workload is distributed among volunteers and staff.
- Publication is not dependent on any one individual.
- The printer can work from the current Google Drive file instead of oversized email attachments.

## Which Pattern Do I Need?

Walk through these questions when planning a new email address:

1. **Does a volunteer or staff member want their own SHHA email mailbox?**
    - Yes → **Personal mailbox** (requires a license; talk to IT admin)
    - No → continue
2. **Is this one of the six designated officer role inboxes that must survive personnel changes?**
    - Yes → **Shared mailbox**
    - No → continue
3. **Does the address need to deliver to a group of people?**
    - Yes → **Mailing list (Microsoft Group)**
    - No → continue
4. **Do you just need a convenient address that routes to an existing mailbox or group?**
    - Yes → **Alias** on the appropriate existing mailbox or group
    - No → talk to IT admin to figure out the right approach

## Task Force Fast Path (Most Common New Setup)

For a new short-term task force, the normal pattern is:

1. Create a **Microsoft 365 Group** for the task-force mailing list.
2. Add members (including external guests) and always include `admin@sandiahomeowners.org`.
3. If the request is for one of the six officer roles, use **SOP B** for the role mailbox. Ordinary committee chairs and task-force leads do not get shared mailboxes.
4. Add an optional **Alias** (for example, `wildfire@sandiahomeowners.org`) if a friendlier address is useful.
5. Confirm the Microsoft 365 group-connected **SharePoint site** exists; do not create a duplicate.
6. Configure document permissions using [SOP: Create a Committee SharePoint Site](/books/shha-it-help-guide/page/sop-create-a-committee-sharepoint-site) and send members the [Committee SharePoint Guide](/books/shha-it-help-guide/page/committee-sharepoint-guide).
7. Test email delivery, update the Quick Links directory, and send the [New Committee Or Task Force](/books/shha-it-help-guide/page/office-onboarding-email-templates) email if this is a new group.

If you only need one address that emails the whole task force, do **SOP A** only.

## SOP A: Create a Microsoft 365 Group (Mailing List)

**Use this for:** any committee/task-force address that should email all members.

**Menu path:** [admin.microsoft.com](https://admin.microsoft.com) → **Teams &amp; groups** → **Active teams &amp; groups** → **Add a group**

### Step-by-step

1. Open [admin.microsoft.com](https://admin.microsoft.com) and sign in.
2. In the left menu, click **Teams &amp; groups**.
3. Click **Active teams &amp; groups**.
4. Click **Add a group**.
5. Select **Microsoft 365** as the group type, then click **Next**.
6. Enter: 
    - **Name**: Full task-force name (example: Wildfire Preparedness Task Force)
    - **Description**: Short purpose statement
    
    Click **Next**.
7. Add at least one **Owner** (usually office staff), then click **Next**.
8. Set: 
    - **Group email address** (example: `wildfiretf` → `wildfiretf@sandiahomeowners.org`)
    - **Privacy**: usually **Private**
    - Leave "Create a team for this group" **off** unless Teams is explicitly needed
    
    Click **Next** then **Create group**.
9. After the group is created, open the new group and go to its **Settings** pane.
10. **Required:** check **Let people outside the organization email this team**.
11. **Required:** check **Send copies of team emails and events to team members' inboxes**.
12. Go to **Members** → **Add members**.
13. Add all task-force members (internal and external as available).
14. **Required:** Add `admin@sandiahomeowners.org` as a member for archive continuity.
15. Send a test email to the new group address and confirm delivery.
16. Send the [New Committee Or Task Force](/books/shha-it-help-guide/page/office-onboarding-email-templates) email after the group, membership, and any SharePoint site are tested.

**Test after every change:** whenever membership or a group setting changes, test the group again. You can add yourself temporarily, send a test message, and remove yourself afterward. If external delivery matters, you can also add a personal Gmail account temporarily, test it, and remove it when finished.

### Done checklist

- Group exists
- Owners added
- All members added
- External email enabled
- Inbox delivery enabled
- `admin@` added
- Test email delivered after setup and after any later change

## SOP B: Create a Shared Mailbox (Six Officer Roles Only)

**Use this only for:** President, Vice President, Secretary, Treasurer, ACC Chair, or CSC Chair. Shared mailboxes are a little fussy to administer, but officer history is important enough that SHHA keeps it this way.

**Do not use this for:** ordinary committee chairs, task-force leads, external volunteers, or general committee communication. Use the person's own account and the committee Microsoft Group instead.

**Menu path:** [admin.microsoft.com](https://admin.microsoft.com) → **Teams &amp; groups** → **Shared mailboxes** → **Add a shared mailbox**

### Step-by-step

1. Confirm the role is one of the six officer roles above. If it is any other chair or lead, stop and use the committee mailing-list procedure.
2. Click **Add a shared mailbox**.
3. Enter the role name and address, such as `president@sandiahomeowners.org`.
4. Save the mailbox, then open its details and choose **Members** → **Edit** → **Add members**.
5. Add the incoming officer's licensed `@sandiahomeowners.org` account.
6. Grant that account both **Full Access** and **Send As**. These are separate permissions; grant both.
7. Send the [Officer Shared Mailbox Access](/books/shha-it-help-guide/page/office-onboarding-email-templates) email with the direct role address and the wiki link.
8. Ask the officer to sign in to [Outlook](https://outlook.office.com) with their own account and manually add the shared mailbox. It will not appear automatically in every Outlook setup.
9. Test that the officer can open the mailbox, read an incoming test message, and send with the role address in the **From** field.
10. Tell the officer to send official role correspondence from the role mailbox or copy it. The shared mailbox is the role's archive; a personal inbox is not.

### Important notes

- The officer does **not** log in directly to the shared mailbox. There is no separate shared-mailbox password to give them.
- For current Outlook instructions, see [Open and use a shared mailbox in Outlook](https://support.microsoft.com/en-us/outlook/sharing/open-and-use-a-shared-mailbox-in-outlook).
- For a change of officer, remove the outgoing officer's permissions, grant the incoming officer both permissions, and test again.

## SOP C: Add an Alias (One-Off Friendly Address)

**Use this for:** addresses like `wildfire@sandiahomeowners.org` that should route to an existing group or mailbox.

**Menu path:** [admin.microsoft.com](https://admin.microsoft.com) → select target group/mailbox → **Email aliases** / **Email address** settings

### Step-by-step

1. Decide destination first: should alias route to the **group** or the **shared mailbox**?
2. For group destination: 
    - Go to **Teams &amp; groups** → **Active teams &amp; groups**.
    - Select the group.
    - Open email settings and add alias address.
3. For shared mailbox destination: 
    - Go to **Teams &amp; groups** → **Shared mailboxes**.
    - Select mailbox.
    - Open email settings and add alias address.
4. Save changes.
5. Send test email to alias and verify it arrives in the expected destination.

## SOP D: Add a licensed user for a volunteer or staff member

**Use this for:** any volunteer requesting an SHHA email address, and staff who need a personal SHHA account (`first.last@sandiahomeowners.org`).

**Menu path:** [admin.microsoft.com](https://admin.microsoft.com) → **Users** → **Active users** → **Add a user**

### Step-by-step

1. Confirm the person wants their own SHHA email address. Volunteers are eligible; being staff or an officer is not a requirement.
2. Check existing users for an account belonging to this person, then check whether a suitable paid license is already available. Ask the authorized license purchaser to arrange a license only if this request needs one. Do not purchase spare licenses.
3. Go to **Users → Active users → Add a user**. Enter the person's name and `first.last@sandiahomeowners.org` username.
4. Generate a temporary password and require a password change at first sign-in. Provide the temporary password through a separate approved channel from the username and welcome instructions.
5. Assign the appropriate license and finish creating the user. Ordinary email users do not need an administrator role.
6. Add the account to the approved committee groups. Grant shared-mailbox permissions only when the person holds one of the six designated officer roles.
7. Have the person sign in to Outlook, receive and send a test message, and open their committee Documents library. Verify the intended account is in use.
8. Send the licensed-user welcome message from the Office Onboarding Email Templates and link the Volunteer with SHHA Email guide.

# SOP: Create a Committee SharePoint Site

**Audience:** SHHA office staff and IT administrators. This is not a committee-member task.

**Goal:** connect an existing committee Microsoft 365 group to its group-owned SharePoint document library, keep site-page administration with office staff, and give committee members read/write access to documents.

## Before You Start

Write down these values before opening Microsoft 365:

<table id="bkmrk-committee-namethe-fu"><tbody><tr><td>**Committee name**</td><td>The full display name</td></tr><tr><td>**Microsoft 365 group**</td><td>The existing group/mailing-list name</td></tr><tr><td>**Group email**</td><td>The committee mailing-list address</td></tr><tr><td>**Expected site address**</td><td>`https://shha.sharepoint.com/sites/[GROUP-NAME]`</td></tr><tr><td>**Office owners**</td><td>Primary and backup office/admin accounts</td></tr></tbody></table>

The finished site should be **Private**. Office staff are Owners / Full Control. Committee members have **Contribute** access to documents and do not administer the home page.

## Step 1: Find The Existing Group-Connected Site

A Microsoft 365 group normally provisions a connected SharePoint team site. If the mailing list already exists, **do not begin by creating another site or group**.

1. Try `https://shha.sharepoint.com/sites/[GROUP-NAME]`.
2. If that does not open, go to [admin.microsoft.com](https://admin.microsoft.com) → **Show all** → **Admin centers** → **SharePoint**.
3. Open **Sites** → **Active sites**.
4. Search for both the committee's full name and group name.
5. In the Microsoft 365 admin center, open **Teams &amp; groups** → **Active teams &amp; groups**, select the group, and confirm its type is **Microsoft 365**.

If the group-connected site appears in Active sites, open it and continue.

**If the Microsoft 365 group exists but no connected site can be found:** do not create a similarly named standalone site. Recheck that the group is a **Microsoft 365** group and search the SharePoint admin center's **Active sites** by both the group name and the full committee name. If the site is still not listed, record the group name and leave site setup pending until Microsoft finishes provisioning it. A duplicate would separate mailing-list membership from document access.

## Step 2: Confirm Office Staff Are Owners

1. In the SharePoint admin center, open **Sites** → **Active sites**.
2. Select the committee site.
3. Select **Membership**.
4. Confirm the primary and backup office/admin accounts are Owners or site admins.
5. Add a backup office/admin owner if needed.
6. Do not make the committee chair or ordinary committee members Owners.

Owners may edit the home page, navigation, permissions, and site settings. Keep that role with office staff.

## Step 3: Give Members Document Access Without Site Editing

Microsoft normally gives group-connected team-site members **Edit** permission. SHHA uses **Contribute** so members can work with documents without managing lists or editing the site page.

1. Open the committee SharePoint site.
2. Select **Settings** → **Site permissions**.
3. Select **Advanced permissions settings**.
4. Select the SharePoint group whose name ends in **Members**. Do not select Owners or Visitors.
5. Select **Edit User Permissions**.
6. Clear **Edit**.
7. Select **Contribute**.
8. Select **OK**.

Do not remove the committee Microsoft 365 group from the site. Group membership keeps the mailing list and document access synchronized.

## Step 4: Keep The Site Simple

A team site already includes a default **Documents** library. Do not create a second Documents library.

1. Open **Documents** and confirm it works.
2. Create a folder named **Documents Shared with Board**.
3. If folder colors are available, apply the standard SHHA committee-folder color.
4. Edit the left navigation and remove unused links. Keep the useful experience limited to **Home** and **Documents**.
5. Do not delete the system **Site Pages** library; it supports the home page.

## Step 5: Make The Home Page Minimal

Only office staff should edit the home page.

1. From the home page, select **Edit**.
2. Use the committee's full name as the title.
3. Add: “Use the Documents library for committee files and enduring reference materials.”
4. Add or keep an obvious link to **Documents**.
5. Remove unnecessary news, activity, and decorative web parts.
6. Republish the page.

## Step 6: Add The Library To Office OneDrive

**This is only for internal office users with SHHA Microsoft accounts.** External users should never use OneDrive for committee documents; they use SharePoint in their browser.

1. Sign in as the office user who needs the shortcut.
2. Open the committee SharePoint site and then **Documents**.
3. Select **Add shortcut to OneDrive** or **Add shortcut to My files**.
4. Open that user's OneDrive and confirm the committee folder appears under **My files**.
5. If the desktop OneDrive app is used, confirm the shortcut appears on that computer.
6. Repeat while signed in as each internal office user who needs the shortcut.

The shortcut points to the group-owned SharePoint library. It does not copy files into a personal OneDrive.

## Step 7: Test With An External Member

1. Ask one existing external group member to open the committee SharePoint site using the same personal email address that received the Microsoft invitation.
2. Confirm the member can open **Documents**.
3. Have the member upload a temporary file named **TEST - delete me**.
4. Confirm the member can edit, rename, move, and delete the test file.
5. Confirm the member cannot edit the home page, navigation, permissions, or membership.
6. Confirm someone outside the group cannot open the private site.
7. Remind the external tester to bookmark the SharePoint site and not use OneDrive.

## Step 8: Publish The Member Instructions

1. Send members the [Committee SharePoint Guide](/books/shha-it-help-guide/page/committee-sharepoint-guide).
2. Add the committee mailing list and SharePoint URL to [Quick Links &amp; Directory](/books/shha-it-help-guide/page/quick-links-directory).
3. Tell external members to bookmark the SharePoint site. Do not give them OneDrive instructions.
4. Send the matching [New Committee Or Task Force](/books/shha-it-help-guide/page/office-onboarding-email-templates) or [New SharePoint Site For An Existing Committee](/books/shha-it-help-guide/page/office-onboarding-email-templates) email.

## Final Checklist

- Existing group-connected site found; no duplicate created
- Site is Private
- Office staff are Owners / Full Control
- Committee members use Contribute permissions
- Documents library works
- Documents Shared with Board folder created
- Home page and navigation simplified
- Office-user OneDrive shortcuts added separately
- External member document test passed through SharePoint
- External member cannot edit the site page
- Directory updated
- General member guide sent
- Matching onboarding email sent

# Understand inherited memberships

**For office staff, membership volunteers and administrators reviewing owners with more than one property.** Start in [Addresses &amp; people](https://toolbox.sandiahomeowners.org/addresses) → **Advanced** → **Quick checks** → **Owners &amp; accounts** → **Ownership &amp; membership**.

## SHHA’s shared ownership membership rule

**SHHA uses shared ownership for membership coverage.** Anyone on a dues-paying property extends membership to other properties they own or co-own. Those additional properties have **inherited membership**; their complete co-owner lists do not have to be identical.

For example, Alice is on dues-paying property A, owns property B and co-owns property C with Bob. The rule extends coverage from A to B and C.

## Why a website members-only export is incomplete

The website does not currently apply shared-ownership coverage. It records each property’s **Is Member** flag; the ownership comparison views are in Toolbox. A property absent from a members-only export may still be covered through shared ownership.

**As of November 18, 2026, SHHA estimates that exporting only website members misses roughly 100 properties under this membership definition.** This is an approximate coverage estimate, not an audited count of dues payments. Check shared ownership before classifying an address as uncovered or choosing an outreach audience.

## Toolbox comparison definitions

Select **Shared ownership** when reviewing SHHA’s coverage rule. The tool retains Individual properties and Identical ownership as alternative comparisons. A comparison result does not update website records or verify SHS billing.

<table id="bkmrk-definitionwhat-it-gr"><thead><tr><th>Definition</th><th>What it groups</th><th>Fictional example</th></tr></thead><tbody><tr><td>Individual properties</td><td>Each property is a separate membership unit.</td><td>Counts A, B and C as three separate units.</td></tr><tr><td>Identical ownership</td><td>Properties group only when their complete lists of linked owners match.</td><td>Alice owns A and B. Alice and Bob own C. A and B group together; C stays separate: two units.</td></tr><tr><td>Shared ownership</td><td>Properties group through a common linked owner, including connected chains of co-owners.</td><td>The same A, B and C group together through Alice: one unit.</td></tr></tbody></table>

The practical difference is often an extra co-owner: “Alice” and “Alice + Bob” are different complete owner lists for Identical ownership, but share Alice for Shared ownership.

The tool’s Shared ownership comparison can also join a chain: Alice owns A, Alice and Bob own B, and Bob owns C. All three group together although neither person owns all three. For a case like this, verify the connection to an actual dues-paying property with the office; the grouping alone does not establish billing or settle how coverage applies through a chain.

## Read the two inherited counts carefully

- **Inherited memberships** is the selected scenario’s count of properties beyond one per group. It can include groups with no property currently marked Member. It is not a count of newly enrolled or paying members.
- **Possible inherited properties / count** identifies properties not marked Member in a group that also contains a property marked Member. These are review candidates; a current Member flag is not billing evidence.

## Review a group before outreach or changes

1. Select **Shared ownership** to review the chosen membership rule. Read **Details** for the definition and example; the other definitions remain available for comparison.
2. Review **Owners**, **All properties &amp; membership**, **Already marked Member**, **Possible inherited properties** and **Possible inherited count**.
3. With **Identical ownership** or **Shared ownership** selected, use **Only possible inherited memberships** to narrow to groups with a recorded Member property and another property not marked Member. Leave it unchecked to see all multi-property groups, including groups whose properties are all marked Member or none are. This checkbox is hidden for Individual properties, which has no inheritance grouping.
4. Check the actual linked owner accounts and address/unit. Matching names do not establish that two accounts are the same person.
5. Identify the dues-paying property and the person’s connection to it, then check their ownership or co-ownership of each additional property. Resolve uncertain ownership or billing with the office. Use the [membership request and review process](/link/44) for a real enrollment request.

Choosing a definition changes the comparison, not dues, property flags, resident links or GRIT delivery. A property whose previous household’s Member flag remains on is a separate record-review issue; it can hide the new resident’s join prompt. See [membership requests and tracking](/link/44).

# Use Welcome Visits for household outreach

**For office staff and welcoming volunteers with approved Welcome Visits access.** Open [Welcome Visits](https://toolbox.sandiahomeowners.org/welcome-visits) from SHHA Toolbox. If access is restricted, ask [office staff](mailto:office@sandiahomeowners.org) or [IT Help](mailto:ithelp@sandiahomeowners.org). The tool tracks household welcome work separately from membership enrollment and SHS billing.

## Find the right household

1. Wait for the list to load. Use **Refresh list** when you need current website information.
2. Choose **Show**. **All visits &amp; history** includes delivered entries; **To visit** hides delivered entries. Use **Needs a volunteer** or **Assigned visits** for assignment work.
3. Search by address, name or volunteer. Check the unit and incoming household, not just the street number.
4. Choose the **Arrival period** and date order. The default period is the past 12 months; use **Choose dates…** for a specific range.
5. Use **Display &amp; more options** for resident type, date details and fields. New tenants can appear in the main visit list even while the owner remains linked. Unconfirmed owner additions are under **Person added / co-owners**.

## Understand the arrival date and membership label

- **Recorded occupancy** comes from the website’s recorded ownership/occupancy start.
- **Estimated arrival** uses resident/address association dates. Account creation is a fallback when a link date is missing. Neither proves a move-in date.
- **Person added / move-in unconfirmed** calls for review; a new account or added co-owner does not by itself establish a new household.
- A committee-entered move-in date takes priority. Review **Move-in dates** when saved and website dates differ.

Membership colors and **Other properties** show website records. They do not confirm payment or automatically determine visit eligibility. Before treating a household as uncovered, check whether membership extends from a dues-paying property through shared ownership. The website’s property flag does not currently capture that extension. Use [SHHA’s inherited membership rule](https://wiki.sandiahomeowners.org/link/46) for multi-property questions and [membership requests and tracking](/link/44) for enrollment.

## Record the welcome work

1. Set the **Volunteer** and add useful **Notes**. Use **Save edit** when the tool shows an unsaved edit; confirm it saved for the committee.
2. Mark **Packet created** only when the welcome packet is prepared.
3. Mark **Delivered** only after delivery. Packet creation and delivery are independent; one does not establish the other.
4. If a visit is not needed, use the rightmost **No visit needed** checkbox. The entry moves to **Show → No visit needed**; assignments, checks and notes are retained.
5. To restore that entry, use **Undo** in the notice or uncheck it under **No visit needed**. This decision applies to the entry, not every later household at the address.

Checkbox changes save shared committee work. Read the save confirmation or error; do not assume a failed save reached other volunteers. Ask the committee lead or office if the household, visit need or packet type is uncertain.

## Use the meeting and packet views

**Meeting view** collapses resident details and history for discussion. Confirm the household’s homeowner/tenant bag label. Use **Bag PDF** or **Cover PDF** for one household and check the address and HOA Unit before preparing the packet.

**Copy view**, **Print list** and CSV can include contact details and notes even when those fields are collapsed on screen. Keep these outputs in approved private committee storage and communication channels.

**Finished?** Check the volunteer, preparation/delivery state and notes for the correct household. A delivered welcome packet does not complete membership enrollment. Send membership intent to the office through the [membership request process](/link/44).

For source record corrections, use [property ownership changes](/link/37) or [manual resident and tenant additions](/link/41). Do not create another ownership change just to give a tenant an arrival date. For help, contact [office staff](mailto:office@sandiahomeowners.org) or [IT Help](mailto:ithelp@sandiahomeowners.org).
